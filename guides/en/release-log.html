v0.9.27

Firmware

New features

  • Alarm tone selection

    Alarms support four built-in tones alongside the original buzzer. Requires MCU ≥0.9.3 plus extension/PWM capabilities. Scheduled/weekly execution and timed/manual stopping remain; older MCUs retain the original buzzer.

    M1 · full, no-frontend-resources
  • MCU RTTTL music and alarm API

    Upload, read, play or stop one RTTTL song and repeat it as an alarm. Requires a separate MCU upgrade to v0.9.3 and capability detection. Up to 1024 ASCII bytes, 256 notes and 180 seconds, retained in dual MCU slots across restart/application OTA. Some pitches are quiet; there is no volume amplification.

    M1 · full, no-frontend-resources
  • CO₂ diagnostics and calibration API

    Expose raw concentration, communication errors and calibration results with legacy reserved-byte compatibility. A 400–1500 ppm reference must be stable for two minutes. Timeouts remain unknown without retries; ACK does not verify accuracy.

    DAIKIN · full

Bug fixes

  • Restore stock temperature and humidity compensation

    Subtract 4.9 °C from temperature. Derive humidity from raw temperature, mixing ratio q × 0.8915 + 0.2632 and corrected temperature, bounded to 0–100%. The fixed stock model is not an independently verified calibration. WebUI supports a custom temperature subtraction (default 4.9 °C), humidity adjustment (default 0 %RH), default restoration and persistent saving with readback confirmation.

    DAIKIN · full

Bundled device pages

New features

  • Formaldehyde/PM threshold editor

    Edit the two formaldehyde/PM thresholds or restore stock values (100/300 and 75/150, raw MCU integers) in Settings → General. Uses persistent settings, preserves the other row’s draft and handles shared revision conflicts.

    M1 · full
  • Web alarm tone selection and preview

    Select and preview four tones on the home and scheduled alarm screens. New options appear only when the actual MCU version and capabilities qualify; existing schedules remain compatible.

    M1 · full
  • RTTTL upload and readback in WebUI

    Paste or import RTTTL text in Settings → General with upload progress and CRC validation before MCU commit. Read it back, play once or stop; select the saved song as an alarm. Hide controls when MCU version or capabilities do not qualify.

    M1 · full
  • CO₂ diagnostics and confirmed calibration in WebUI

    General settings show module diagnostics and send calibration once after environment and final confirmation. Older firmware hides the controls; records last only for this boot.

    DAIKIN · full

v0.9.26

Firmware

New features

  • Persistent DAIKIN indicator rules

    CO₂, TVOC and PM each support up to two thresholds with steady on/off and fast/slow blink. The PM lamp selects PM2.5 or PM10. Formaldehyde rules are available when its module is detected. Rules survive restart; unmatched or stale readings turn the lamp off.

    DAIKIN · full
  • Weighted filter usage and estimated airflow

    Switch between elapsed-time and stock weighted models while both counters keep running. Switching does not reset them; existing settings retain their model and runtime, while filter reset clears both. Airflow is estimated from speed, not measured.

    A1 · full, no-frontend-resources, fresh-air, fresh-air-no-frontend-resources
  • One-time and weekly wake alarms

    Schedule one-time or weekly wake alarms with web preview and stop controls. The device executes tasks once its clock is valid, independently of an open browser.

    M1 · full, no-frontend-resources
  • Stock thresholds and MCU status

    Persist stock two-level formaldehyde/PM2.5 threshold writes, handle negative temperatures, and expose sensor health, MCU version and buzzer controls.

    M1 · full, no-frontend-resources
  • CO2 screen replacement and alternation

    With a detected CO2 module and capable MCU, keep, replace or alternate the formaldehyde/PM number position and configure CO2 thresholds. Requires open MCU v0.9.2; hide the original label/unit and show four-digit concentrations in decimal thousands.

    M1 · full, no-frontend-resources
  • MCU network OTA and extended debugging

    Add an authenticated MCU network-upgrade bridge and tool. Companion MCU v0.9.2 restores stock sensor/display cadence and PM branches, with threshold colors/alarms, CO2 and 0x70 debugging. The MCU remains a separate developer preview.

    M1 · full, no-frontend-resources

Improvements

  • DAIKIN Wi-Fi lamp shows system state

    The system lamp uses three long and three short pulses when unconfigured, fast blink for disconnected Wi-Fi, slow blink while configured MQTT is not ready, and steady on when ready. It is independent of the air quality indicator switch.

    DAIKIN · full
  • Consistent DAIKIN recovery hotspot

    The recovery hotspot uses BRY88AX151K-AP- followed by the last six uppercase MAC digits, with IP and gateway 192.168.0.1. Startup, button recovery and network-failure reopening share this configuration; saved Wi-Fi and MQTT settings remain.

    DAIKIN · full
  • DAIKIN downloads use the model prefix

    New assets use the daikin_BRY88AX151K prefix; normal upgrades use daikin_BRY88AX151K.ota.bin.signed. Historical archives retain their names, and the older transition image in the stock OTA guide retains its original hotspot.

    DAIKIN · full

Bundled device pages

New features

  • DAIKIN indicator settings page

    Edit thresholds, comparison conditions and four light patterns in Settings → General → Indicator rules, including the PM data source. The overview previews current patterns and keeps blink timing across refreshes.

    DAIKIN · full

    All website demos add a home link, including updated DAIKIN indicator settings. The project introduction describes open-source firmware for discontinued IoT devices or devices whose cloud services have ended.

v0.9.23

Firmware

New features

  • Optional fresh-air firmware and second fan

    The fresh-air variant uses serial TX for PWM and RX for tachometer input and requires compatible wiring and fans. It supports independent power, manual/automatic mode, polarity and output mapping, defaults to two pulses per revolution, and exposes fresh-air MQTT/Home Assistant entities.

    A1 · fresh-air, fresh-air-no-frontend-resources
  • Dual-fan coupling policies

    Fresh-air speed can be independent, limited by the main fan or raise the main fan’s minimum speed. Powering off the unit stops both channels and preserves existing binding settings.

    A1 · fresh-air, fresh-air-no-frontend-resources

    A1 PWM runs at 25 kHz; the standard variant retains the original fan-driver mapping.

    A1 · full, no-frontend-resources, fresh-air, fresh-air-no-frontend-resources
  • Reduce fresh-air configuration overhead

    Reduces temporary policy allocations and page size, retains the 16 KiB memory guard and may still return busy under heavy load.

    A1 · fresh-air, fresh-air-no-frontend-resources

Important changes

  • Fresh-air wiring and startup limitations

    The off level is not guaranteed during fresh-air cold power-on or boot; confirm compatible wiring before use. Full-variant OTA space is very limited; a fresh-air minimal variant retains setup pages.

    A1 · fresh-air, fresh-air-no-frontend-resources

Bundled device pages
