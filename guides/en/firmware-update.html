Firmware updates

This page covers web OTA after community firmware is installed. Factory devices need their model-specific first installation. M1 can use factory LAN migration, starting with 0.9.21 or newer; do not upload the community signature wrapper to the factory interface.

Check for updates on the device

Official builds provide GitHub Pages HTTPS and domestic/international HTTP update sources. Choose a source in the firmware settings and check:

  • The UI distinguishes a new version, already up to date and network failure.
  • Switch sources and retry if a network request fails.
  • Check the model, version and release notes, then explicitly download and install. Checking never installs an update automatically.

You can read release notes for the selected version. Use Cancel download during transfer; cancellation, network timeout or failure restores normal services. A retry starts from the beginning. Cancellation is unavailable after the final commit starts.

Choose the correct file

File Purpose
.ota.bin.signed Signed OTA package for web upload and MQTT / URL installation; P-256 / SHA-256 signature verification is mandatory
.ota.bin.raw Native image for an explicitly supported first migration or unsigned recovery; factory M1 migration uses the full image from 0.9.21 or newer
.all.bin Full image for wired flashing; never upload it as OTA

Use the GitHub archive on the project downloads page, choose your exact product and verify SHA256SUMS from that release. The device verifies the header signature before erasing, and activates the new image only after Flash readback SHA-256 and compatibility checks pass.

Install a local file

Online demos use simulated data. On a real device:

  1. Open its firmware update page.
  2. Select and upload the verified .ota.bin.signed file.
  3. Keep power connected throughout writing and the automatic reboot.
  4. Reopen the WebUI and check the running version.

Unsigned recovery from older community firmware may use .ota.bin.raw under its specific procedure. Firmware supporting that option accepts it after selecting Allow unsigned firmware. Factory M1 uses the separate factory upload procedure; later normal updates still use signed packages.

Recovery

Updates pause linkage and other business responses while keeping update status and cancellation available. Reduce concurrent access during an update; sustained multi-client pressure updating has not passed full acceptance.

If the WebUI is reachable, check the file, model, version and network, then retry. If the device cannot boot, use the corresponding wired recovery guide: TC1, M1 / A1. Normal OTA updates do not require opening the device.

Full and slim firmware

Default files include the complete device UI. Files containing -no-frontend-resources keep an offline setup page for Wi-Fi, initial MQTT settings and the web password, available through the device hotspot or LAN address. Use local device management or IotCloud for full controls and settings. Both share the same appearance. MQTT is not required to complete Wi-Fi setup.

Online checks stay on the current firmware variant. To switch variants manually, select the signed package for the same physical product.
